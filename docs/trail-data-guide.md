# 등산로·지도 데이터 수집 가이드

> 대상: 등산로 데이터를 모아 줄 팀원
> 목적: 2단계(코스 매칭·정복 랭킹)에 쓸 등산로 데이터를 같은 형식으로 모으기

---

## 1. 이 데이터가 어디에 쓰이나

기획서(`docs/planning.md`) 3~4장의 기능이 모두 "등록된 코스"를 기준으로 동작한다.

| 기능 | 필요한 데이터 |
|---|---|
| 코스 매칭 (3.5) | 코스 경로(선) — 사용자 기록과 겹침 비율을 계산 |
| 코스별 정복 랭킹 (4.1) | 산 > 코스 구조, 코스 이름 |
| 최단시간은 등정 구간만 인정 (4.6) | **들머리 → 정상 방향**으로 순서가 맞는 경로, 정상 좌표 |
| 등산로 탐색 (3.4) | 지역, 거리, 공식 난이도·소요시간 |
| 위험 구간 표시 | 급경사·낙석 등 지점 좌표 |

**지도(배경 지도 이미지·타일)는 지금 모으지 않는다.** 배경 지도는 나중에 지도 SDK를 정하면 그 SDK가 제공한다. 우리가 직접 모아야 하는 것은 **경로와 지점의 좌표**다.

---

## 2. 수집 범위 (1차)

처음부터 전국을 모으지 않는다. 형식과 매칭 로직을 검증할 수 있는 만큼만 모은다.

- **산 3~5개**
  - 팀원이 직접 가 볼 수 있는 산 2~3개 (실제 기록으로 매칭 테스트용)
  - 이용자가 많은 유명 산 1~2개 (코스가 여러 개라 매칭이 까다로운 사례)
- **산마다 주요 코스 2~4개**
- 코스 하나 = **들머리 1곳 → 정상** (편도, 오르는 방향)
  - 하산 코스가 다르면 별도 코스로 적는다.
  - 원점회귀 코스도 "오르는 길"과 "내려오는 길"로 나눠 적는다.

산 목록과 담당자는 팀에서 정한 뒤 6장 표에 적는다.

---

## 3. 수집 방법 (출처)

### 3-1. 공공데이터 (우선)
- **공공데이터포털**(data.go.kr)에서 "등산로", "탐방로", "산 정보"로 검색한다.
  - 산림청, 국립공원공단, 지자체가 등산로 노선(SHP, GeoJSON 등)과 산 정보를 제공한다.
- **산림청 산림공간정보 서비스**, **국가공간정보포털**에도 등산로 공간 데이터가 있다.
- 받은 데이터마다 **이용 조건(공공누리 유형)** 을 반드시 적는다.
  - 1유형: 출처 표시 시 상업적 이용·변경 가능 → **가장 좋음**
  - 2유형: 상업적 이용 불가 → 우리 서비스는 구독 BM이 있으므로 주의
  - 3·4유형: 변경 불가 → 좌표 정리·분할이 어려움

### 3-2. OpenStreetMap
- openstreetmap.org에서 등산로(`highway=path`, `highway=footway` 등)를 내려받을 수 있다.
- 라이선스는 ODbL이다. **출처 표시가 필요하고, 가공한 데이터베이스를 공개해야 할 수 있다.** 사용 여부는 팀에서 결정하고, 일단 받으면 출처를 꼭 적는다.

### 3-3. 직접 기록한 GPX (적극 권장)
- 실제로 산에 가서 휴대폰 등산 앱(GPX 내보내기가 되는 앱)으로 기록한다.
- 공공데이터 경로가 실제와 얼마나 다른지 확인하고, **매칭 로직 테스트 데이터**로 바로 쓴다.
- 기록할 때: 위치 정밀도 "높음", 절전 모드 끄기, 들머리에서 시작해 정상에서 한 번 끊기(가능하면).

### 3-4. 쓰지 않는 것
- 블로그·카페 글, 다른 등산 앱(트랭글, 램블러 등)의 GPX를 **내려받아 그대로 쓰지 않는다.** 저작권·약관 문제가 있다. 참고해서 보는 것은 괜찮다.

## 4. 정리 방식

### 4-1. 공통 규칙
- **좌표계: WGS84 (EPSG:4326), 경도·위도 순서.** GPS와 같은 좌표계다.
  - 공공데이터 SHP는 EPSG:5186, 5179 같은 한국 좌표계인 경우가 많다. **QGIS**(무료)로 열어서 EPSG:4326으로 변환해 저장한다.
- **파일 형식**
  - 코스 경로: GeoJSON (`LineString` 하나 = 코스 하나). GPX도 괜찮다.
  - 산 목록, 지점: CSV
- **방향**: 코스 경로의 점 순서는 **들머리 → 정상**.
- **문자 인코딩**: UTF-8 (한글 깨짐 방지)

### 4-2. 폴더 구조 (공유 드라이브)
```
trail-data/
  mountains.csv                 # 산 목록
  raw/                          # 받은 원본 그대로 (수정하지 않음)
    {출처}_{받은날짜}/
  courses/
    {산이름}/
      {산이름}_{코스이름}.geojson
      points.csv                # 이 산의 지점(들머리, 정상, 갈림길, 위험 구간)
  gpx/
    {산이름}_{코스이름}_{YYYYMMDD}_{기록자}.gpx
```
원본은 공유 드라이브에 두고, 정리가 끝난 데이터만 나중에 저장소로 옮긴다. 직접 기록한 GPX 중 테스트에 쓸 것은 저장소의 `test_data/`에도 넣는다.

### 4-3. `mountains.csv` (산 목록)
| 열 | 예시 | 설명 |
|---|---|---|
| mountain_name | 관악산 | |
| region | 서울 관악구 | 시·도 + 시·군·구 |
| summit_name | 연주대 | 정상 이름 |
| summit_lat | 37.4448 | 정상 위도 |
| summit_lon | 126.9640 | 정상 경도 |
| height_m | 632 | 높이 |
| source | 공공데이터포털 ○○ | 출처 |

※ 예시 좌표는 형식 설명용이다. 실제 값은 출처에서 확인해 적는다.

### 4-4. 코스 GeoJSON의 `properties`
```json
{
  "type": "Feature",
  "properties": {
    "mountain_name": "관악산",
    "course_name": "서울대입구 코스",
    "start_name": "관악산공원 입구",
    "end_name": "연주대",
    "direction": "ascent",
    "distance_m": 4200,
    "official_time_min": 120,
    "official_difficulty": "보통",
    "source": "공공데이터포털 ○○ 데이터",
    "source_url": "https://...",
    "license": "공공누리 1유형",
    "collected_at": "2026-10-20",
    "collector": "홍길동",
    "notes": ""
  },
  "geometry": { "type": "LineString", "coordinates": [[126.95, 37.46], [126.96, 37.45]] }
}
```
- 모르는 값은 비워 둔다. 짐작해서 채우지 않는다.
- `direction`: `ascent`(오르는 길) / `descent`(내려오는 길)

### 4-5. `points.csv` (지점)
| 열 | 예시 | 설명 |
|---|---|---|
| mountain_name | 관악산 | |
| type | trailhead / summit / junction / danger / viewpoint | 들머리 / 정상 / 갈림길 / 위험 / 조망 |
| name | 깔딱고개 | |
| lat, lon | | |
| note | 급경사, 겨울 결빙 | |
| source | | |

### 4-6. 제출 전 확인
- [ ] **geojson.io**에 파일을 끌어다 놓았을 때 경로가 실제 산 위에 그려진다 (좌표계가 맞는지 확인)
- [ ] 경로가 중간에 끊기지 않는다
- [ ] 점 순서가 들머리 → 정상이다
- [ ] 경로 길이가 공식 거리와 대략 맞다 (±10% 이내)
- [ ] 출처와 라이선스를 적었다

---

## 5. 질문이 생기면
- 출처 데이터에 코스 이름이 없거나, 한 노선이 여러 코스에 걸쳐 있으면 **원본은 그대로 두고** `notes`에 상황을 적은 뒤 팀 채널에 공유한다.
- 정리 방식이 애매하면 산 하나를 먼저 끝까지 정리해서 공유하고 형식을 맞춘 뒤 나머지를 진행한다.
